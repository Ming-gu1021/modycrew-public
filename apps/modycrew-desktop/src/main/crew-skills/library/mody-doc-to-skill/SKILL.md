# 문서로 업무 스킬 만들기

회사 문서에 흩어진 업무 절차를 근거 위치와 함께 정리해, AI가 같은 순서로 따라 할 수 있는 업무 스킬과 사람이 읽는 인수인계 문서를 만든다.

## 언제 쓰나

- 규정·매뉴얼·회의록·양식·메일 사본에 흩어진 업무를 하나의 절차로 정리할 때.
- 담당자 교체에 대비한 인수인계 문서나 반복 업무용 SKILL.md가 필요할 때.
- 쓰지 않는 경우: 원본 문서 수정·서식 변환, 법률·세무 해석 확정.

## 실행 환경

- 현재 폴더가 작업 폴더다. 요청 원문은 `REQUEST.md`에 있다.
- 사용자가 폴더를 지정했다면 `TARGET.md`에 경로와 권한(읽기 또는 수정)이 있다. 읽기 권한이면 그 폴더의 파일을 바꾸지 않는다.
- 결과 파일은 `output/` 아래에만 만든다. 수정 권한을 받은 대상 폴더만 예외다.
- 함께 쓰라고 지정된 설치 스킬이 `.claude/skills` 또는 `.agents/skills` 아래에 있으면 그 SKILL.md를 먼저 읽는다.
- `TARGET.md`의 원본 폴더는 권한이 수정이어도 이 스킬에서는 읽기만 하고, 결과는 항상 `output/`에 만든다.
- 동반 스킬 hwp, rhwp-edit이 있으면 SKILL.md를 먼저 읽되 원본 HWP 파일에는 쓰지 않는다. 변환에 명령 실행이 필요하면 이 스킬의 허용 도구 밖이므로 '변환 필요'로 남긴다.
- 패키지 설치처럼 네트워크가 필요한 단계는 실행하지 않고 필요 항목으로 적는다.
- 외부 게시·배포·발송·결제·삭제·대량 다운로드는 하지 않고 승인 필요로 남긴다.
- 마지막 응답은 한국어로 쓴다: 한 줄 결론, 만든·바꾼 파일 목록, 실제로 확인한 것과 확인하지 못한 것, 사용자 승인 필요 항목.

## 먼저 확인할 것

1. 읽을 범위(폴더·파일)와 정리할 업무 이름. 업무 이름이 없으면 문서에서 업무 후보를 최대 5개 뽑아 제안하고, 근거가 가장 많은 1개를 먼저 만든다.
2. 파일 목록은 Glob으로 만든다. 한 번에 최대 100개 파일을 읽고 나머지는 '미열람'으로 적는다. 읽는 순서는 규정·매뉴얼 → 양식·서식 → 회의록·메일 → 기타.
3. 형식: md·txt·csv·html·json은 읽고, PDF·이미지는 실행기가 읽을 수 있을 때만 읽는다. hwp·hwpx·docx·xlsx·pptx처럼 텍스트로 읽히지 않는 파일은 '읽기 실패(형식)'로 적고 텍스트·PDF 사본을 요청 항목으로 남긴다.
4. 수정일: 문서 안의 개정일·작성일 표기를 먼저 쓰고, 도구로 파일 수정일을 알 수 있으면 함께 적는다. 둘 다 없으면 '미상'.
5. 민감 정보는 Grep으로 먼저 찾는다.
   - 주민등록번호 `\d{6}-?[1-8]\d{6}`, 휴대전화 `01[016789]-?\d{3,4}-?\d{4}`
   - 계좌·카드 번호(숫자 10~16자리 묶음), `비밀번호`·`password`·`api_key`·`secret`·`token`
   - 급여·건강·집 주소처럼 개인을 특정하는 정보

## 절차

1. **자료 목록**
   - 파일 경로, 형식, 수정일, 원문 버전, 읽기 상태를 적는다.
   - 원문 버전은 작업 폴더의 `SOURCE-MANIFEST.md`(실행기가 실행 전에 만든 대상 폴더 파일 목록과 SHA-256)에서 앞 12자리를 옮긴다. 목록에 없는 파일은 '미측정'이다.
   - 산출물: `output/source-index.md` 초안
2. **읽기와 위치 기록**
   - 업무와 관련된 부분마다 위치(쪽, 절 번호, 제목, 표 번호, 줄 번호 중 확인 가능한 것)를 적는다.
   - 인용은 한 위치당 2문장 이내로 하고 나머지는 요약한다.
   - 산출물: source-index.md의 '사용한 부분' 열
3. **민감 정보 표시**
   - 찾은 값은 결과에 옮기지 않고 '민감 정보 있음(파일 경로 · 위치)'로만 적는다.
   - 산출물: source-index.md의 '민감 정보' 열
4. **업무 구조화**
   - 업무마다 목적, 담당(직무명), 주기, 입력, 출력, 단계, 예외 처리를 뽑는다.
   - 단계마다 근거를 붙인다. 근거가 없는 단계는 만들지 않고 '확인 필요'에 적는다.
   - 산출물: 업무 절차 표
5. **충돌 정리**
   - 같은 항목의 내용이 문서마다 다르면(예: 결재 한도 50만 원과 100만 원) 두 내용을 근거와 함께 모두 적고 확정하지 않는다.
   - 날짜가 더 늦은 쪽에는 '최신으로 보임'만 표시한다.
   - 산출물: handover.md의 '확인 필요'
6. **업무 스킬 작성**
   - `output/skills/<업무-이름>/SKILL.md`를 Agent Skills 규격으로 쓴다.
   - name: 영문 소문자·숫자·하이픈, 64자 이하. 하이픈으로 시작·끝나거나 하이픈이 연속되면 안 되고, 폴더 이름과 같아야 한다.
   - description: 1024자 이하. 무엇을 하는지와 언제 쓰는지(요청 표현 3개 이상)를 함께 쓴다.
   - 본문: 단계마다 끝에 `근거: 파일 경로 · 쪽/절`을 붙인다. 본문은 500줄 이하.
   - 본문 끝 '원문 버전' 절에 근거로 쓴 파일의 source-index 번호와 SHA-256 앞 12자리를 적는다. 원문이 바뀌면 이 스킬을 다시 만들어야 하는지 알 수 있게 한다.
   - 산출물: 업무 스킬 SKILL.md
7. **인수인계 문서**
   - 업무 개요, 담당과 주기, 업무 절차 표, 입력과 출력, 예외 처리, 연락처 자리표시, 확인 필요를 쓴다.
   - 산출물: `output/handover.md`
8. **자체 점검**
   - 모든 단계에 근거가 있는지, 민감 정보 원문이 0건인지, name 규칙을 지켰는지, 원본 경로에 쓰기 도구를 쓰지 않았는지 확인한다.
   - 산출물: 마지막 응답의 '실제로 확인한 것'

## 결과물 형식

- `output/source-index.md` — `| 번호 | 파일 경로 | 형식 | 수정일 | 원문 SHA-256(앞 12자리) | 읽기 상태 | 사용한 부분 | 민감 정보 |` (읽기 상태: 읽음·일부·실패(사유)·미열람)
- `output/skills/<업무-이름>/SKILL.md`
  - 앞부분: `name`, `description` 두 필드
  - 본문 제목 순서: 목적 / 입력과 출력 / 절차 / 예외 처리 / 확인 필요 / 원문 버전
  - 단계 예: `3. 구매 요청서를 팀장 결재로 올린다. 근거: 규정/구매관리규정.pdf · 12쪽 3.2절`
- `output/handover.md` — 목차: 1. 업무 개요 / 2. 담당과 주기 / 3. 업무 절차 표 / 4. 입력과 출력 / 5. 예외 처리 / 6. 연락처 / 7. 확인 필요
  - 업무 절차 표: `| 단계 | 할 일 | 담당 | 입력 | 출력 | 근거 |`
  - 연락처: `{담당 부서}`, `{담당자 연락처}` 같은 자리표시만 쓴다.
  - 확인 필요: `| 항목 | 내용 A(근거) | 내용 B(근거) | 확인할 사람 |`

## 승인·안전 기준

- 원본 파일을 수정·이동·삭제·이름 변경하지 않는다.
- 민감 정보 원문을 결과 파일, 로그, 마지막 응답에 쓰지 않는다.
- 결과를 메일·메신저·드라이브로 공유하지 않고 승인 필요로 남긴다.
- 법·세무·노무 판단이 들어간 단계는 '전문가 확인 필요'로 표시한다.

## 하지 않는 것

- 문서끼리 충돌할 때 한쪽을 골라 확정하기.
- 읽지 못한 파일의 내용을 추정해 채우기.
- 원문을 길게 복사하기(인용은 위치당 2문장 이내).
- 실명·개인 연락처를 인수인계 문서에 옮기기.
