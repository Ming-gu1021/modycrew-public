# 디자인팀 기본 절차

어떤 AI가 실행해도 요구 정리 → 화면 구조 → 토큰 → 시안 → 검수 → 인계 순서와 같은 파일 규격으로 결과를 낸다.

## 언제 쓰나

- 새 화면, 랜딩 페이지, 배너, 와이어프레임 시안이 필요할 때.
- 기존 화면 개선안, 작은 화면·접근성 검수, 개발 인계 명세가 필요할 때.
- 쓰지 않는 경우: 실제 서비스 코드 수정(mody-dev-crew), 로고·일러스트 원화(이미지 도구 필요).

## 실행 환경

- 현재 폴더가 작업 폴더다. 요청 원문은 `REQUEST.md`에 있다.
- 사용자가 폴더를 지정했다면 `TARGET.md`에 경로와 권한(읽기 또는 수정)이 있다. 읽기 권한이면 그 폴더의 파일을 바꾸지 않는다.
- 결과 파일은 `output/` 아래에만 만든다. 수정 권한을 받은 대상 폴더만 예외다.
- 함께 쓰라고 지정된 설치 스킬이 `.claude/skills` 또는 `.agents/skills` 아래에 있으면 그 SKILL.md를 먼저 읽는다.
- 동반 스킬과 쓰는 때: 새 화면 hallmark, 기존 화면 진단 improve-ui(원본은 읽기만), 빠른 정리 baseline-ui, 세부 다듬기 make-interfaces-feel-better, 접근성 fixing-accessibility, 참고 화면·저장소에서 규칙 추출 design-md-from-reference·create-design-md.
- ui-ux-pro-max가 설치돼 있으면 디자인 시스템 후보를 찾을 때 그 검색 스크립트를 쓴다(`python <스킬 폴더>/scripts/search.py "<질의>" --design-system`). 표준 라이브러리만 쓰고 네트워크를 쓰지 않는다. 없으면 설치하지 않고 이 문서 기준으로 진행한다.
- 스킬끼리 지시가 다르면 사용자 브랜드 자료 → 이 문서 → 동반 스킬 순으로 따른다.
- 패키지 설치처럼 네트워크가 필요한 단계는 실행하지 않고 필요 항목으로 적는다.
- 외부 게시·배포·발송·결제·삭제·대량 다운로드는 하지 않고 승인 필요로 남긴다.
- 마지막 응답은 한국어로 쓴다: 한 줄 결론, 만든·바꾼 파일 목록, 실제로 확인한 것과 확인하지 못한 것, 사용자 승인 필요 항목.

## 먼저 확인할 것

1. 목적과 핵심 행동 1개(예: 신청하기, 문의하기).
2. 대상 사용자와 사용 환경. 정하지 않았으면 모바일 우선으로 만든다.
3. 브랜드 자료(색·글꼴·로고·말투)와 대상 폴더의 기존 디자인 시스템(DESIGN.md, design-system/MASTER.md, 토큰·테마 파일, 공용 컴포넌트). 있으면 그것이 기준이고 새 토큰을 만들지 않는다. 둘 다 없으면 배경 #FFFFFF, 글자 #111827, 강조 #2563EB를 쓰고 '가정'으로 표시한다.
4. 실제 문구와 데이터. 가격·일정처럼 받지 못한 정보는 지어내지 않고 '추후 안내'로 둔다.
5. 결과 형태. 사용자가 '명세만'이라고 했으면 `prototype.html` 없이 `handoff.md`에 화면 명세를 쓴다.
6. 이미지 도구 연결 여부. 없으면 이미지 자리는 회색 상자와 대체 텍스트로 두고, 필요한 이미지 조건(대상·장면·구도·스타일·출력 비율)을 적는다.

## 절차

1. **요구 정리**
   - 목적·대상·환경·브랜드·핵심 행동·제약·완료 기준·가정을 쓴다.
   - 산출물: `output/design-brief.md`
2. **화면 구조**
   - 화면마다 정보 우선순위(1~5), 핵심 행동 1개, 처음 보이는 정보와 펼쳐 보는 정보를 나눈다.
   - 상태는 기본·빈 화면·오류·로딩 4개를 기본으로 하고, 입력 폼이 있으면 처리 중·성공을 더한다.
   - 산출물: design-brief.md의 '화면 구조와 상태'
3. **디자인 시스템**
   - 기존 디자인 시스템이 있으면 그 이름과 값을 그대로 옮겨 적고, 빠진 것만 새로 정의한다.
   - 색: 배경·표면·글자·보조 글자·강조·오류·성공·경계선. 글자·배경 색 쌍마다 대비 값을 적는다.
   - 글자: 제목1·제목2·본문·캡션의 크기·줄 높이·굵기. 본문 16px 이상, 줄 높이 1.5 이상.
   - 간격 4·8·12·16·24·32·48px, 모서리 0·4·8·16px와 원형 999px, 그림자 없음·약·중 3단계.
   - 컴포넌트 규칙: 버튼·입력·카드·알림의 상태(기본·마우스 올림·누름·포커스·비활성·오류)와 움직임(150~300ms, 움직임 줄이기 설정이면 끔).
   - 산출물: `output/design-tokens.md`
4. **시안 제작**
   - `output/prototype.html` 한 파일. 외부 글꼴·이미지·CDN 없이 인라인 CSS·JS만 쓰고 토큰은 CSS 변수로 둔다.
   - 실제 문구를 넣고, 화면 위 전환 버튼과 주소 해시(#default, #empty, #error, #loading)로 상태를 바꾼다.
   - 모바일 우선 배치에서 시작해 768px·1280px에서 배치를 바꾼다.
   - 누르는 요소는 44x44px 이상, 포커스 표시는 2px 이상 외곽선이며 배경과 대비 3:1 이상.
   - 누르는 요소 사이 간격은 8px 이상, 마우스 올림에만 기대는 기능을 만들지 않고, 아이콘만 있는 버튼에는 이름(aria-label)을 단다.
   - 오류 문구는 무엇이 문제인지와 고치는 방법을 함께 쓰고 입력값을 지우지 않는다. 원인을 모르면 단정하지 않는다.
   - 산출물: `output/prototype.html`
5. **검수**
   - 아래 14개 항목을 통과·실패·미확인으로 판정하고, 근거 칸에 '코드 확인' 또는 '화면 확인'을 적는다.
   - 브라우저로 직접 보지 못한 항목을 '화면 확인'으로 적지 않는다.
   - 산출물: `output/qa-checklist.md`
6. **수정**
   - 실패 항목만 고치고 같은 항목을 다시 검수한다. 최대 2회 반복하고 남은 실패는 그대로 기록한다.
   - 산출물: 갱신한 prototype.html과 qa-checklist.md
7. **개발 인계**
   - 화면별 구성요소·상태·간격·토큰·문구와 남은 결정을 쓴다.
   - 산출물: `output/handoff.md`

## 결과물 형식

- `output/design-brief.md` — 목차: 1. 목적과 핵심 행동 / 2. 대상과 사용 환경 / 3. 브랜드 조건 / 4. 화면 구조와 상태 / 5. 완료 기준 / 6. 가정과 빈 정보
- `output/prototype.html` — 단일 파일. 맨 위 주석에 화면 목록과 상태 전환 방법을 적는다.
- `output/design-tokens.md` — 디자인 시스템. `| 분류 | 토큰 이름 | 값 | 용도 | 대비 |` 표와 컴포넌트 규칙 표 `| 컴포넌트 | 상태 | 규칙 |`, 맨 위에 기존 디자인 시스템 사용 여부와 경로
- `output/qa-checklist.md` — `| 번호 | 항목 | 기준 | 판정 | 근거 |`, 항목은 다음 14개로 고정한다.
  1. 360px 폭: 가로 스크롤 없음
  2. 768px 폭: 겹침·잘림 없음
  3. 1280px 폭: 본문 한 줄이 한글 40자·영문 80자 이내
  4. 200% 확대: 글자 잘림·겹침 없음
  5. 본문 글자 명도 대비 4.5:1 이상
  6. 큰 글자(24px 이상, 굵게 18.66px 이상)·아이콘·경계선 대비 3:1 이상
  7. 터치 영역 44x44px 이상
  8. 키보드 포커스 순서가 화면을 읽는 순서와 같음
  9. 모든 조작 요소에 포커스 표시가 보임
  10. 의미 있는 이미지에 대체 텍스트, 장식 이미지는 빈 alt
  11. 오류 문구에 원인과 해결 방법이 있고 입력값이 유지됨
  12. 마우스 올림에만 기대는 기능이 없음
  13. 움직임 줄이기(prefers-reduced-motion) 설정에서 애니메이션이 꺼짐
  14. 아이콘만 있는 버튼에 이름(aria-label)이 있음
- `output/handoff.md` — 목차: 1. 화면 목록 / 2. 화면별 구성요소 / 3. 상태별 동작 / 4. 문구 목록 / 5. 남은 결정
  - 구성요소 머리글: `| 화면 | 구성요소 | 상태 | 간격 | 토큰 | 문구 |`
  - 남은 결정 머리글: `| 항목 | 선택지 | 결정할 사람 | 기한 |`

## 승인·안전 기준

- 외부 게시·배포와 브랜드 기준 확정은 사용자 승인 뒤에 한다.
- 이미지·영상은 연결된 생성 도구가 있을 때만 만든다. 모델만 연결된 경우 이미지·영상을 만들었다고 쓰지 않는다.
- 사용권을 확인하지 않은 다른 회사 로고, 유료 글꼴, 스톡 이미지는 넣지 않는다.
- 가짜 후기·고객사 로고·성과 수치를 넣지 않는다. 예시 값에는 '예시' 표시를 단다.

## 하지 않는 것

- 읽기 권한 폴더나 `output/` 밖의 파일 수정.
- 확인하지 않은 검수 항목을 통과로 적기.
- 서로 다른 스타일 지시를 섞어 방향이 둘 이상인 시안 만들기.
- 정상 화면만 만들고 빈 화면·오류·로딩 상태를 빼기.
