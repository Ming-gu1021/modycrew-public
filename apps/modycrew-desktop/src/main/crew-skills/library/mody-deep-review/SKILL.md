# 심층 검토(여러 AI 교차 검토)

한 AI의 답을 바로 채택하지 않고 독립 답변 → 익명 교차 검토 → 의장 종합의 3단계를 거쳐 결론을 낸다. 의견 차이는 지우지 않고 근거와 함께 남긴다.

## 언제 쓰나

- 되돌리기 어려운 결정: 출시 범위, 가격, 계약 조건, 데이터 구조, 보안 설계, 여러 파일에 걸친 코드 변경안.
- 사용자가 '심층 검토', '교차 검토', '크로스체크', '여러 AI 의견', 'LLM 카운슬', '다른 AI한테도 물어봐'라고 요청할 때.
- 이미 받은 AI 답이 2개 이상이고 결론이 서로 달라 판정이 필요할 때.
- 쓰지 않는 경우: 정답이 하나인 사실 확인, 맞춤법, 단순 번역. 일반 답변으로 처리한다.

## 먼저 확인할 것

1. 검토 대상 원문(기획서, 설계안, 코드 변경 diff, 결정 메모)이 있는가. 없으면 받은 설명만으로 진행하고 질문 요약에 '원문 미제공'이라고 쓴다.
2. 결정 기준. 사용자가 정하지 않았으면 정확성·위험·실행 비용 3가지를 기본 기준으로 쓴다.
3. 참여 실행기. 모디크루에 연결된 실행기(예: Codex, Claude)와 모델 이름을 적는다. 2개 이상이면 교차 검토, 1개이거나 다른 AI의 답을 직접 받을 수 없는 환경이면 관점 분리 검토다.
4. 사용량. 참여 AI가 N개면 호출은 최소 2N+1회(1단계 N회, 2단계 N회, 종합 1회)다. 구독 사용량이나 요금이 든다는 점을 시작 전에 알린다.
5. 증거. 코드면 테스트 결과·오류 로그, 기획이면 수치의 출처가 있는지 본다.
6. 원문에 비밀번호·접속 키·개인정보가 있으면 다른 실행기로 보내기 전에 `****`로 가린다.

## 절차

1. **질문 고정**
   - 검토 대상, 결정 기준(3개 이하), 제약, 원하는 결과를 5문장 이내의 '질문 카드'로 쓴다.
   - 모든 참여 AI에 글자 하나 바꾸지 않고 같은 카드를 준다.
   - 산출물: 질문 카드
2. **1단계 독립 답변**
   - 참여 AI마다 다른 답을 보지 않은 채 결론 1문장, 근거 최대 5개(근거마다 출처나 증거 위치), 위험 최대 3개, 확인 방법을 쓴다.
   - 단계 상태는 대기·진행·완료·실패·중단 중 하나로 기록한다. 실패한 AI는 빼고 진행하되 상태표에 남긴다. 남은 AI가 1개면 관점 분리 검토로 바꾼다.
   - 산출물: 참여 AI 수만큼의 독립 답변
3. **익명화**
   - 답에서 모델 이름과 자기 언급을 지우고 무작위 순서로 A, B, C를 붙인다.
   - 글자와 AI의 대응표는 3단계가 끝날 때까지 평가자에게 보이지 않는다.
   - 산출물: 익명 답변 묶음, 비공개 대응표
4. **2단계 교차 검토**
   - 참여 AI가 3개 이상이면 각 AI가 자기 답을 뺀 익명 답을 평가하고, 2개면 비교가 되도록 두 답을 모두 익명으로 평가한다.
   - 평가 항목: 사실 오류, 빠진 위험, 근거 강도(강·중·약), 정확성과 통찰 기준의 순위, 순위 이유 1문장.
   - 산출물: 평가자별 평가표와 순위
5. **3단계 의장 종합**
   - 의장은 사용자가 지정한 AI, 지정이 없으면 모디크루 기본 실행기다.
   - 모든 답의 결론이 같고 근거가 확인된 것만 '합의'로 적는다.
   - 결론이 다르면 근거와 테스트 증거가 더 강한 쪽을 최종안에 쓰고, 다른 쪽은 남은 이견으로 남긴다. 찬성한 AI 수가 많다는 이유만으로 채택하지 않는다.
   - 근거 강도가 같으면 최종안에 '사용자 결정 필요'를 적는다. 이 단계에서 대응표를 공개한다.
   - 산출물: 합의·이견·최종안 초안, 공개한 대응표
6. **근거 표시**
   - 최종안의 주장마다 '확인됨(증거 위치)', '추정', '확인 필요' 중 하나를 붙인다.
   - '확인 필요'에는 검증 방법·담당·완료 기준을 적는다.
   - 산출물: 확인 필요·다음 검증 목록
7. **보고**
   - 아래 형식으로 쓴다. 사용자가 중간에 멈추면 완료된 단계까지만 쓰고 나머지 단계 상태를 '중단'으로 둔다.
   - 산출물: 최종 보고

관점 분리 검토에서는 같은 AI가 기획·개발·검증 세 관점으로 1단계를 따로 쓰고(앞 관점의 답을 참고하지 않는다), 검증 관점이 2단계를 맡는다. 결과 첫 줄은 `단일 AI 관점 분리 검토(교차 검증 아님)`이다.

## 결과물 형식

아래 제목을 이 순서와 문구 그대로 쓴다. 내용이 없으면 제목 아래에 '해당 없음'이라고 쓴다.

1. 질문 요약 — 질문 카드 원문, 5문장 이내
2. 참여 AI와 단계별 상태 — `| 참여 AI(모델) | 익명 | 1단계 독립 답변 | 2단계 교차 검토 | 3단계 종합 | 사용량 |`
3. 답변 요지 비교표 — `| 익명 | 결론 | 핵심 근거 | 주요 위험 | 확인 방법 |`
4. 익명 교차 검토 요지 — `| 평가자 | 평가 대상 | 사실 오류 | 빠진 위험 | 근거 강도 | 순위 | 이유 |`
5. 합의된 점 — 최대 5개, 항목마다 근거
6. 남은 이견 — `| 쟁점 | 누가 | 무엇을 | 왜(근거) | 판정에 필요한 증거 |`
7. 최종안 — 결론 1문장, 실행 단계 최대 5개, 채택하지 않은 대안과 이유
8. 확인 필요·다음 검증 — `| 항목 | 근거 수준 | 검증 방법 | 담당 | 완료 기준 |`

## 승인·안전 기준

- 시작 전에 참여 AI 목록과 예상 호출 수를 보여 준다. 구독에 포함되지 않은 유료 호출이 생기면 사용자 승인 뒤에 진행한다.
- 사용자가 중단을 요청하면 진행 중인 단계를 멈추고 그때까지의 결과만 보고한다.
- 다수결을 정답으로 취급하지 않는다. 근거·테스트 증거가 없는 다수 의견은 '추정'으로 표시한다.
- 최종안에 외부 발송, 배포, 계약, 결제, 삭제가 들어 있으면 '사용자 승인 필요'로 표시하고 직접 실행하지 않는다.

## 하지 않는 것

- 실제로 호출하지 않은 AI의 답을 지어내거나, 한 AI가 다른 AI 이름으로 답을 쓰지 않는다.
- 이견을 평균 내거나 지워서 하나의 의견처럼 만들지 않는다.
- 2단계 평가자에게 답의 작성자를 알려 주지 않는다.
- 관점 분리 검토를 교차 검증이라고 부르지 않는다.
- 검토 결론에 따라 코드 수정·배포·발송을 직접 하지 않는다.

- 모디크루 요구로 더한 것: 사용 모델·진행 상태·사용량 표시, 중단, 이견 보존, 다수결 배제, 근거·테스트 증거 우선, 단일 AI 관점 분리 표시.
