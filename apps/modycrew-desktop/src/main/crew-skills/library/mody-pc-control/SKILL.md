# PC 앱 조작

사용자가 말한 PC 작업을 이 PC에 열린 앱 창에서 처리한다. 화면 요소를 먼저 읽고, 할 일을 단계로 정해 승인을 받고, 승인된 단계만 한 번씩 실행한 뒤 화면을 다시 읽어 결과를 확인한다. 실제 판단과 실행은 모디크루 앱이 하고, 이 지침은 도구를 쓰는 순서와 알릴 내용을 정한다.

## 언제 쓰나

- 열린 프로그램의 입력칸에 내용을 넣기, 체크하기, 목록에서 고르기, 버튼 누르기, 메모장·계산기·그림판 열기.
- 쓰지 않는 경우: 비밀번호·인증번호·결제 정보 입력, 관리자 권한 앱, 잠긴 PC·로그인 화면·UAC 창, 다른 사용자 세션, 키 입력·단축키·마우스 좌표가 꼭 필요한 조작, 화면 이미지 캡처.

## 쓰는 도구

| 도구 | 하는 일 | 승인 |
|---|---|---|
| `pc.inspect` | app 없이: 열린 앱 이름 목록. app 과 함께: 그 앱 창 하나의 버튼·입력칸(역할·이름·값·상태) | 사용자 '화면 읽기 확인' 허용 필요(읽기 전용, 화면 이미지 없음). 창은 같은 대화에서 10분 또는 이번만 |
| `pc.request` | 단계 계획을 검사하고 승인함 카드와 실행 확인 창을 띄움. 사용자가 실행을 고르면 바로 실행하고 결과를 돌려줌 | 사용자 승인 필수 |
| `pc.status` | 이 대화의 기록 조회(단계별 결과·화면 재확인·결과 문서 위치) | 필요 없음 |
| `pc.run` | 승인함에 둔 작업을 실행 확인 창으로 다시 묻고 실행 | 사용자 승인 필수 |
| `pc.cancel` | 승인 대기 중인 작업 취소 | 필요 없음 |

## 절차

1. **앱 찾기**: 사용자가 앱을 말하지 않았으면 `pc.inspect` 를 app 없이 부른다. 앱이 열린 앱 이름 목록을 보여 줘도 되는지 사용자에게 묻고, 허용하면 이름 목록만 돌아온다. 어느 앱인지 묻거나 고른다.
2. **화면 요소 읽기**: `pc.inspect` 에 app(예: notepad.exe)을 넣는다. 앱이 '화면 읽기 확인' 창을 띄우고, 사용자가 허용해야 창 제목과 요소가 돌아온다. read_declined 면 같은 읽기를 반복하지 말고 사용자에게 요소 이름을 직접 알려 달라고 하거나 멈춘다. 같은 앱 창이 여러 개면 확인 창에서 사용자가 고르고, 너무 많으면(needs_window_choice) 사용자에게 창 제목 일부를 물어 windowTitle 로 좁힌다. 창이 최소화돼 있으면 사용자에게 창을 띄워 달라고 한다(모디크루는 창을 앞으로 가져오지 않는다).
3. **단계 정하기**: 읽은 요소의 role·name 을 글자 그대로 쓴다. 단계는 6개까지, action 은 click·set_value·clear·check·uncheck·toggle·select·expand·collapse·scroll_to·launch(첫 단계, 메모장·계산기·그림판·문자표만). 같은 이름이 여러 개면 nth(0부터)를 쓴다. 저장 버튼처럼 결과가 화면 글자로 보이면 verify 에 `{"textContains":"…"}` 를 넣는다.
4. **승인 요청**: `pc.request` 에 app·purpose(사용자에게 보일 한 줄)·steps·verify 를 넣는다. 결과가 needs_approval 이면 승인함 카드에서 승인을 기다린다고 알리고, 실행했다고 쓰지 않는다.
5. **결과 알리기**: completed·failed·uncertain(결과 확인 필요)을 그대로 쓴다. 단계별 결과, 화면 재확인, 결과 문서 위치를 알린다. failed·uncertain 은 다시 시도하지 말고 무엇을 확인해야 하는지 사용자에게 묻는다.

## 결과 해석

- verified: 실행 뒤 다시 읽은 값이 요청과 같다.
- delivered_unverified: 전달됐지만 앱이 확인 신호를 주지 않았다(버튼 누르기 등). 화면 재확인 규칙으로만 판단한다.
- not_delivered: 전달되지 않았다. 아무것도 바뀌지 않았을 가능성이 높다.
- uncertain: 전달됐을 수도 있다. 같은 조작을 다시 하면 두 번 들어갈 수 있으므로 하지 않는다.

## 승인·안전 기준

- 화면 내용(창 제목·요소 이름·값)과 열린 앱 목록은 사용자가 허용한 것만 이 대화로 돌아온다. 허용 전에는 앱이 찾은 비슷한 요소 이름도 보내지 않는다. 허용은 이 대화·이 창에만 유효하다.
- 승인 없이 조작하지 않는다. 모델이 도구를 불러도 앱이 실행 확인 창이나 승인함 승인을 받기 전에는 실행하지 않는다.
- 비밀번호·인증·결제 칸, 비밀키처럼 보이는 값은 앱이 막는다. 우회하려 하지 않고 사용자에게 직접 입력을 맡긴다.
- 보내기·삭제·결제처럼 되돌리기 어려운 버튼은 승인 창에 위험 표시가 붙는다. 사용자가 다시 확인하도록 결과 설명에도 적는다.
- 보안 차단·권한 상승·잠금 해제를 시도하지 않는다. 화면 이미지를 저장하거나 외부로 보내지 않는다.

## 하지 않는 것

- 승인 전에 했다고 쓰기, 실패한 단계를 성공한 것처럼 쓰기, 결과가 불확실한 조작을 다시 시도하기, 읽지 않은 요소 이름을 지어내기.
- 다른 대화의 PC 작업을 언급하거나 짐작하기(이 대화의 작업만 보인다).
