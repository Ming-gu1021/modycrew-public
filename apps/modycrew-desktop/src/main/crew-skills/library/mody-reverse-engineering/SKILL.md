# 기능 분석(리버스 엔지니어링)

권한이 있는 프로그램의 사본을 REA 분석 도구로 살펴 무엇을 하는지 정리하고, 그 결과로 모디크루가 독자 구현할 요구사항과 검증 계획을 만든다. 확인한 사실, 추정, 확인하지 못한 것을 섞지 않는다.

## 언제 쓰나

- 우리 회사 앱·설치본·APK의 이전 버전 동작 확인, 허용된 오픈소스 바이너리의 기능 파악, 경쟁 제품 기능을 공개 자료와 허용된 범위에서 비교해 독자 구현 요구사항을 뽑을 때.
- 쓰지 않는 경우: 라이선스 키·인증·복제 방지·DRM 해제, 접근 제한 우회, 남의 서버 공격, 원본 코드 복제.

## 실행 환경

- 실행기가 사용자가 고른 파일·폴더를 작업 폴더의 `target-copy/`로 복사해 둔다. 원본 경로는 `TARGET.md`에만 있고 원본은 열지 않는다.
- REA 분석 도구(MCP 서버 rea)만 쓸 수 있다. 다른 연결 도구와 네트워크는 쓰지 않는다.
- 대상 프로그램을 실행하지 않는다. 정적 분석(파일 구조, 함수, 문자열, 디컴파일 결과)만 한다.
- 결과 파일은 `output/` 아래에만 만든다. 마지막 응답은 한국어로 쓴다: 한 줄 결론, 만든 파일, 확인한 것과 못 한 것, 승인 필요 항목.

## 분석 도구 버전 주의(2026-11-02 점검)

- REA 6.8.0 은 Ghidra 12.1.x 만 받아서 이 PC의 REA 는 Ghidra 12.1.4 를 쓴다. 12.1.4 에는 12.2 에서만 고쳐진 공개 보안 권고가 남아 있다.
- 출처를 모르는 파일을 분석할 때 하지 않는다: Ghidra 로 압축 묶음(zip·tar·7z)을 바로 가져오기, Ghidra 테마·확장 가져오기, 디버거(ssh-gdbserver 포함)·Ghidra Server·BSim 연결, 분석 결과의 주석·문자열 속 링크(@url 등) 열기. 링크는 글자로만 기록한다.
- Ghidra GUI(12.2)에서 저장한 프로젝트나 데이터 타입 파일을 REA 에 넘기지 않는다. 12.2 에서 고친 파일은 12.1.4 에서 못 읽을 수 있다.
- REA 가 알려 준 Ghidra 버전이 12.1.4 가 아니면 그 버전과 REA 판정(compatible·unsupported)을 '확인하지 못한 것'에 적는다.
- APK 분석에 쓰는 jadx-headless-mcp 0.7.1 은 큰 APK 에서 첫 클래스 조회가 오래 걸릴 수 있다. REA 가 버전을 고정하므로 JAR 을 바꾸지 않는다.

## 먼저 확인할 것

1. 요청에 적힌 대상의 소유·분석 권한과 목적. 권한이 확인되지 않으면 분석하지 않고 필요한 확인을 적는다.
2. 대상 형식: Windows 실행 파일, Electron·웹 번들, APK·JAR, 펌웨어 등. REA 도구 목록에서 형식에 맞는 도구를 고른다.
3. 비교할 기존 모디크루 기능과 목표 결과물.

## 절차

1. **대상·권한·범위 확인**
   - 대상 이름, 형식, 크기, 분석 목적, 허용 근거를 표로 적는다.
2. **가벼운 조사부터**
   - REA로 파일 정보·구조·포함 모듈·문자열을 먼저 보고, 필요한 기능 부분만 함수·디컴파일까지 내려간다.
   - 도구 호출마다 무엇을 확인했는지 근거(함수 이름·주소·파일 경로)를 남긴다.
3. **사실·추정·미확인 분리**
   - 확인한 사실: 도구 결과로 직접 보인 것. 추정: 이름·문자열·구조로 미뤄 본 것과 그 이유. 확인하지 못한 것: 도구가 실패했거나 실행해야 알 수 있는 것.
4. **요구사항 추출**
   - 사용자 행동, 입력과 출력, 예외 처리, 외부 연결을 요구사항 문장으로 쓰고 근거를 붙인다.
5. **기존 기능 대조**
   - 요구사항마다 모디크루에 이미 있음·일부 있음·없음을 적는다.
6. **구현·검증 계획**
   - 원본 코드를 옮기지 않는 독자 구현 계획, 라이선스가 허용한 재사용 범위, 검증 방법(테스트·실제 실행)을 쓴다.

## 결과물 형식

- `output/re-findings.md` — 제목 순서: 1. 대상·권한·범위 / 2. 확인한 사실 `| 번호 | 사실 | 근거(함수·주소·파일) | 사용한 도구 |` / 3. 추정 `| 번호 | 추정 | 이유 | 확인 방법 |` / 4. 확인하지 못한 것 `| 항목 | 이유 | 필요한 조치 |`
- `output/requirements.md` — `| 번호 | 요구사항 | 근거(사실 번호) | 우선순위 |`
- `output/comparison.md` — `| 요구사항 | 모디크루 현재 | 부족한 점 | 구현·검증 계획 |`

## 승인·안전 기준

- 권한이 확인된 대상의 사본만 분석한다. 보호 장치·인증·라이선스 검사를 해제하거나 우회하는 방법을 찾지 않는다.
- 원본 코드·이미지·문구를 결과물에 옮겨 쓰지 않는다. 동작 설명과 독자 구현 계획만 남긴다.
- 대상 실행, 네트워크 사용, 분석 결과 외부 전송을 하지 않는다.

## 하지 않는 것

- 확인하지 않은 추정을 사실로 적기, 도구가 실패한 부분을 분석한 것처럼 적기.
- 비슷한 이름의 저장소나 제품을 근거 없이 출처로 연결하기.

## 출처와 라이선스

- REA(rea-agents 6.8.0, npm): 설치 패키지 README 가 공식 출처로 밝힌 곳(github.com/morluto/rea·rea.tools·npm)과 GitHub 릴리스 rea-agents-6.8.0 의 package.json 이 이 PC 설치본과 같다(2026-11-02 확인). 라이선스는 package.json 의 MIT. 이름이 비슷한 다른 저장소는 출처로 쓰지 않는다. 설치본을 재사용하며 새로 설치하지 않는다.
- reverse-engineer-anything 스킬(version 49, 이 PC 설치): 이 PC에 있으면 실행 때 함께 읽는 동반 스킬이다. 이 문서는 그 원문을 옮기지 않고 모디크루 규칙으로 새로 썼다.
